\# InsightFlow 示例报告



\## 制造业设备维护知识问答研究



\[查看报告](manufacturing-maintenance-report-v0.1.md)



\### 研究问题



检索增强生成（RAG）如何应用于制造业设备维护知识问答？

这些应用对 MES 运维有哪些参考价值？



\### 生成方式



\- 基于 Local Deep Researcher 二次开发的研究工作流。

\- 模型通过 OpenRouter 调用。

\- 使用 ddgs 检索网页。

\- 配置一轮搜索，关闭网页全文抓取。

\- 根据搜索摘要生成中文总结，并附上来源列表。



\### 本示例展示什么



\- 从研究主题生成搜索词并执行真实网页检索。

\- 将检索资料整理为发现、应用建议和待验证问题。

\- 正文通过来源标题标注，末尾由程序附上原始链接。

\- 将研究结果保存为可阅读的 Markdown 文件。



\### 阅读限制



这是一次真实运行的原始输出，保留了待改进的表述，

用于展示当前系统能力，不代表经过独立核验的研究结论。



\- 输入主要是搜索摘要，未系统核对全文。

\- 来源中的质量控制与多模态研究，对设备维护的支持偏间接。

\- 项目作者宣称的“生产级”等能力未经本项目验证。

\- 有引用不代表每条结论都得到充分支持。

\- 搜索结果与模型输出可能随运行时间变化。



\### 人工审阅发现



1\. 应将 GitHub 项目的能力描述明确归因于项目作者。

2\. 对常规 RAG 局限性的描述，应归因于具体论文作者，

&#x20;  避免将摘要中的观点写成普遍成立的结论。

3\. 未获取评测设置与结果时，应表述为“本次未取得验证证据”，

&#x20;  而非断言相关项目没有做过验证。

4\. 对 MES 的建议需要进一步缩小范围，并给出验证方法。
